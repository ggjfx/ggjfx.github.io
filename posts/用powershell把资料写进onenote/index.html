起因#

我在准备专升本，笔记用的是 OneNote 2016。AI 帮我整理的知识点、出的试卷，一直是生成 HTML 和 PDF——但资料躺在文件夹里，跟我平时看笔记的地方是两个世界。

于是有了这个需求：让 AI 直接把内容写进 OneNote 的分区里，我打开笔记本就能看到。

最后是做成了：高数分区下面写进去了 2 页试卷 + 13 页知识点（总目录 + 12 章），每章还做成了左右双栏。但过程相当曲折，这篇把坑全记下来，下次不用再撞一遍。

技术路线：COM 接口#

OneNote 2016 提供 COM 接口，PowerShell 里一行就能连上：

$on = New-Object -ComObject OneNote.Application

能读层级、建页面、写内容、调页面顺序。注意这是 OneNote 2016 桌面版才有的，UWP 那个"OneNote for Windows 10"没有这套接口。

坑 0：OneNote 没开着，连不上#

直接 New-Object 会报 CO_E_SERVER_EXEC_FAILURE。解决办法是先启动进程再等一会儿：

Start-Process "C:\Program Files\Microsoft Office\root\Office16\ONENOTE.EXE"
Start-Sleep -Seconds 30

30 秒不算夸张，我试过 10 秒还是连不上。

坑 1（最惨的一个）：别对文件夹调 OpenHierarchy#

我一开始的思路很自然：笔记本就是个文件夹，那我遍历文件夹、找到 .one 文件、逐个打开不就行了？

于是我对笔记本文件夹调了 OpenHierarchy。

OneNote 的反应是：它把这个文件夹当成了一个"新笔记本"，然后在里面自动创建了一个默认分区 打开笔记本.one。

而我的脚本下一步是 Get-ChildItem *.one，于是它又把这个刚生成的垃圾分区当成正常分区打开……每跑一次，每个文件夹就多一个 打开笔记本 N.one。

我跑了 7 次。49 个垃圾分区。

清理花了不少时间（用 DeleteHierarchy 删 + 把文件移到备份目录）。教训写在这里：

笔记本只要在 OneNote 里注册过，用 GetHierarchy("", 4, [ref]$xml, 2) 就能全读到，根本不需要 OpenHierarchy。

一行就够，别自己造轮子。

坑 2：命名空间和 schema 参数必须配对#

写页面用 UpdatePageContent($xml, $date, $schema)。这里有个组合陷阱：

  • 用 2013 命名空间 http://schemas.microsoft.com/office/onenote/2013/onenote + schema 参数 2（xs2013）→ ✅ 正常
  • 用 2007 命名空间 → 报 0x8004200B
  • 2007 命名空间配 schema 1 或 2 → 报 0x80042001

枚举值就四个（xs2007 / xs2010 / xs2013 / xsCurrent，对应 0..2），别猜，直接用 2013 + 2。

读页面也一样：GetPageContent($id, [ref]$xml, 0, 0) 会让 OneNote 直接崩溃（RPC failed 0x800706BE）。schema 参数也得传 2。这个坑我踩了两次，第一次以为是 OneNote 本身不稳。

坑 3：写十几页以后，它就写不进去了#

批量写内容的时候会遇到这个：UpdatePageContent 开始一直报 0x80042030。换新页面不行、把 XML 简化到只剩一行文字也不行，看着像内容有问题。

其实是 OneNote 自己进入了一种写不进去的状态。关掉重开就好了。

所以现在我的批量脚本是"写十几页就主动重启一次 OneNote"，稳定多了。

坑 4：PowerShell 读 XML 属性，别用点语法#

这个坑最阴。读分区 XML 找页面时，我写的是：

$pages | Where-Object { $_.name -eq '第一章' }   # 永远匹配不到

原因：XmlElement 自己有个内置的 Name 属性（元素名，比如 one:Page），跟 XML 里的 name="第一章" 属性打架了。不报错，就是静默匹配失败，最难查的那种。

正确写法：

$pages | Where-Object { $_.GetAttribute('name') -eq '第一章' }

同理，取 ID 用 GetAttribute('ID')。

实际怎么写内容#

摸清之后，写页面的流程比想象的简单——不需要先读出来再改 DOM：

  1. CreateNewPage($sectionId, [ref]$pageId) 拿到新页面 ID；
  2. 自己拼一整页 XML（<one:Page ID='...'> + Title + Outline / OEChildren / OE / T）；
  3. UpdatePageContent($xml, [DateTime]::MinValue, 2) 一次性交上去。

正文放 CDATA 里，而且 CDATA 里的 HTML 标签 OneNote 会正常解析，这点很好用：

  • <b>重点</b> → 粗体
  • <sup>2</sup> → 上标（写数学公式必需）
  • <span style='background:#FFF2A8'>公式</span> → 行内黄色底纹

读回来的时候会变成 font-weight:bold 的 span，这是正常的，不是写坏了。

表格#

表格 XML 长这样，shadingColor 可以给单元格上底色（我拿来做答题栏和答案格）：

<one:OE><one:Table bordersVisible="true" hasHeaderRow="true">
  <one:Columns><one:Column index="0" width="70"/>…</one:Columns>
  <one:Row><one:Cell shadingColor="#DEEAF6"><one:OEChildren>…</one:OEChildren></one:Cell></one:Row>
</one:Table></one:OE>

双栏布局#

知识点页我做成了左右分栏：左边是详细知识点，右边是"初高中衔接"（讲这一章要用到的初中高中基础）。实现方式是一页放两个 Outline，用 Position 定位：

  • 主栏：x=36，宽 700
  • 右栏：x=756，宽 360

读回验证的时候注意：Outline 标签会带 author、objectID 这些属性，正则匹配要写宽松点，否则会误判成没写进去。

调页面顺序#

UpdateHierarchy($sectionXml, 2)。这里第二个参数是 schema（2），不是日期——我一开始按 UpdatePageContent 的签名习惯传了日期，一直失败。

做法：取分区 XML → 把目标 Page 节点移到最前 → 整段回写。我用它把"总目录"页排到了 12 章前面。

其它零碎坑#

  • 删页面 + 新建 会留下"未命名"空页。每批跑完得清一次残留。
  • DeleteHierarchy 之后旧页可能又出现：笔记本在 OneDrive 上，云端同步有延迟，页面在层级里还没消失。重跑一次删除就行，不是脚本的问题。
  • 笔记本搬到 OneDrive 之后，路径变成 URL 了：https://d.docs.live.net/xxxx/文档/专升本/。所以原来 -like '*\高数\知识点.one' 这种反斜杠匹配全废，得改成 *高数*知识点.one。
  • OneNote 重启后 GetHierarchy 只给当前打开的笔记本，被移动或关闭的笔记本会直接消失。所以要先确认返回的 Notebook 节点，再往下找分区。
  • exec 里内联 PowerShell 命令，$变量 会被外层吞掉。我现在一律写成 .ps1 文件再执行，不再内联。
  • PowerShell 5.1 读没有 BOM 的 UTF-8 脚本，中文会乱码（按 GBK 解析了）。写完脚本用 Node 补个 BOM：'\uFEFF' + s，这已经成了固定套路。

成果#

现在整条链是这样的：

Markdown / HTML 资料 → Node 脚本解析成 JSON → 生成 OneNote 页面 XML → PowerShell COM 写入 → 读回校验（数几个表、几段、多少字）

校验这步很重要。我不是"写完就当成功"，而是读回来数一遍：12 章是不是都有 2 个 Outline、页序是不是 00 → 第十二章、有没有残留空页。写自动化最怕的就是静默半成功。

打开 OneNote 就能看到自己的知识点、试卷、答案详解，跟手写笔记放一起——这件事折腾了两个晚上，但值。
