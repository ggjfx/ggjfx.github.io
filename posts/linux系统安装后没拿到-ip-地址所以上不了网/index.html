第一次输出：我学到了什么？#

这次网络排障，你实际上掌握了一套完整的网络排障方法论，而不仅仅是几个命令。来，我们把知识点分类列出来：

计算机网络基础#

  1. DNS（域名系统）的本质：它是互联网的“电话本”，把人类好记的域名（如 baidu.com）翻译成机器能识别的 IP 地址。报错 Name or service not known 就是查不到这个电话本。
  2. IP 地址的概念：互联网上每台设备的“门牌号”。8.8.8.8 是 Google 的公共 DNS 服务器地址，常被用作网络连通性测试的目标。
  3. 网络不可达（Network Unreachable）的含义：数据包在本地网络就迷路了，根本没踏上通往互联网的路。这通常意味着网关缺失或物理连接有问题。
  4. 排障的“分层思维”：从物理层（网线/WiFi）→ 网络层（IP地址）→ 传输层（路由/网关）→ 应用层（DNS），一层一层往上查，这是网络工程师最核心的思维方式。

Linux 系统管理#

  1. sudo 和 sudoers 文件：sudo 是“临时借用管理员权限”的命令，但只有被列入 /etc/sudoers 文件的用户才能使用。报错 not in the sudoers file 说明你的账户没有被授权。
  2. su - 命令的正确用法：su - 是“完全切换用户身份”，包括环境变量。- 这个横杠很重要，没有它你可能连 PATH 都加载不全。
  3. root 用户的权限边界：root 是系统的“超级管理员”，可以做任何事情，但也意味着“手滑一下系统就崩了”。所以平时用普通用户，必要时才切 root。

Linux 网络排障命令#

  1. ip route 命令：查看路由表，相当于看“出门地图”。如果输出为空，说明没有默认网关，数据包不知道往哪儿送。
  2. ip addr 命令：查看网卡信息和 IP 地址，相当于看“自家的门牌号和门锁状态”。
  3. dhclient 命令：手动向路由器申请 IP 地址，相当于“拿着身份证去物业登记，领一张门禁卡”。
  4. ping 命令的高级用法：ping 8.8.8.8 测试网络连通性，ping baidu.com 测试 DNS 解析。两者结合能快速定位问题出在哪一层。
  5. /etc/resolv.conf 文件：DNS 配置文件，里面写着你电脑的“电话本”地址。添加 nameserver 8.8.8.8 就等于告诉系统：“查电话本去这个地址查。”

编程思维与排障方法论#

  1. “现象 → 定位 → 解决 → 验证”的闭环：你不是瞎猜乱试，而是有逻辑地一步步缩小问题范围，最后精准命中。
  2. “最小复现原则”：先用最简单的命令（ping 8.8.8.8）测试最基本的功能，排除干扰因素。
  3. “从底层往上查”的思维习惯：物理连接 → IP 地址 → 网关 → DNS，这是网络排障的黄金顺序。

第二次输出：我们做了什么 & 容易踩哪些坑？#

过程回顾：我们一起追查了“网络迷路案”#

我们一起走过了一条非常清晰的排障路线，就像侦探破案一样：

  • 第一步：发现症状。你敲了 ping daidu.com，系统说“查无此人”（Name or service not known）。这就像你打电话给朋友，但通讯录里没存他的名字。
  • 第二步：缩小范围。你又敲了 ping 8.8.8.8，系统说“路不通”（Network is unreachable）。这就像你明明知道朋友家的门牌号，但发现自己被困在小区里出不去。
  • 第三步：查找原因。你输入 ip route，结果返回一片空白。这就像你打开导航地图，发现上面没有任何路线，连小区大门的位置都没标出来。
  • 第四步：定位根源。你输入 ip addr，发现网卡根本没拿到 IP 地址。这就像你搬进新家，但物业还没给你分配门牌号。
  • 第五步：解决权限问题。你想用 sudo dhclient -v 去申请 IP，但系统说“你没有管理员权限”（cyh is not in the sudoers file）。这就像你想找物业经理办事，但保安说你没在访客名单上。
  • 第六步：切换身份。你用 su - 切换到 root 用户，拿到了最高权限。这就像你亮出了房产证，保安立刻放行。
  • 第七步：手动获取 IP。你执行 dhclient -v，成功从路由器那里租到了一个 IP 地址。这就像物业终于给你发了门牌号。
  • 第八步：验证成功。你再敲 ping daidu.com，这次通了！你终于能出门了。

踩坑指南：新手常犯的网络“傻瓜”错误#

网络这东西看不见摸不着，新手特别容易犯以下几个错误，你看看有没有中招：

  • 坑一：以为连着 WiFi 图标就有网
    • 现象：屏幕右上角 WiFi 图标是满格的，但就是上不了网。
    • 真相：你只是连上了“路由器”这个邻居大爷，但大爷家的宽带可能欠费了，或者网线没插好。你和外网是断联的，但和局域网是通的。
    • 比喻：就像你进了小区大门（连上 WiFi），但发现小区外的城市大道堵死了（宽带断了）。
  • 坑二：虚拟机网络模式设成了“仅主机模式” (Host-Only)
    • 现象：如果你是在虚拟机（VMware/VirtualBox）里装的系统，这是最常见的死法。
    • 真相：你设置了“仅主机模式”，意思就是这台电脑只能和自己玩，完全切断了和外网的连接。这简直就是给自己建了一个孤岛。
    • 比喻：就像你为了安全，把家门焊死了，只留了一扇窗户给自己通风，外面的人根本进不来，你也出不去。
  • 坑三：IP 地址冲突或设置为手动但填错了
    • 现象：网卡显示已连接，但 Ping 任何地址都是 Network is unreachable。
    • 真相：你的电脑拿到的 IP 地址和别人“撞车”了，或者你手动设置 IP 时，网关填错了一个数字。
    • 比喻：就像你给自己的车挂了一个和别人一模一样的车牌号，交警（网络）直接把你们俩都拦截了，谁也动不了。
  • 坑四：防火墙过于激进
    • 真相：有时候 Linux 自带的防火墙默认拒绝所有出站连接，导致你连 Ping 都发不出去。
    • 比喻：就像你为了防止小偷，把家里所有的门和窗都反锁了，结果连送外卖的也进不来。
  • 坑五：DNS 缓存作祟
    • 现象：你改了 /etc/resolv.conf 里的 DNS 服务器地址，但 ping 域名还是报错。
    • 真相：系统可能还在用旧的 DNS 缓存。你需要清一下缓存。
    • 比喻：就像你换了手机号，但朋友手机里存的还是你以前的号码，打过来当然找不到你。
    • 避坑：可以试试 systemctl restart network 或者 nscd -i hosts 来清缓存。
  • 坑六：/etc/resolv.conf 被自动覆盖
    • 现象：你手动编辑了 /etc/resolv.conf，但重启网络或重启系统后，里面的内容又变回原来的样子了。
    • 真相：某些网络管理工具（如 NetworkManager）会自动管理这个文件，你手动改的会被覆盖。
    • 比喻：就像你偷偷改了物业的住户名单，但第二天物业系统自动同步，又把你的修改覆盖掉了。
    • 避坑：要么禁用 NetworkManager，要么在它的配置文件里设置固定的 DNS。

第三次输出：以后可以怎么玩得更好？#

既然你已经亲手打通了网络，尝到了“排障成功”的甜头，接下来就该想想怎么把这份能力转化成更值钱的技能了。我给你三个方向，你可以挑一个最感兴趣的先玩起来。

玩点一：给你的网络做个“自助体检套餐”（Shell 脚本自动化）#

  • 想达到什么效果：每次网络出问题，你都要手动敲 ping、ip addr、ip route 这一套。能不能写一个脚本，一键执行全套检查，然后直接告诉你“问题出在第几步”？
  • 可以尝试什么技术：Shell 脚本 + 条件判断（if…else…fi）+ 变量。
  • 实现思路（大白话）：
    1. 创建一个脚本文件，比如叫 check_network.sh。
    2. 脚本里按顺序执行我们排障的四步：
      • 第一步：ping -c 1 8.8.8.8，如果通了，打印“✅ 外网可达”；如果没通，打印“❌ 外网不可达，检查网关”。
      • 第二步：ip route | grep default，如果有结果，打印“✅ 网关存在”；如果没有，打印“❌ 网关缺失”。
      • 第三步：ip addr show eth0 | grep ‘inet ‘，如果有 IP，打印“✅ 网卡有 IP”；如果没有，打印“❌ 网卡无 IP”。
      • 第四步：ping -c 1 baidu.com，如果通了，打印“✅ DNS 解析正常”；如果没通，打印“❌ DNS 可能有问题”。
    3. 最后给脚本加上执行权限（chmod +x check_network.sh），以后网络出问题，直接运行 ./check_network.sh，它就像个体检机一样，一口气告诉你哪里病了。

玩点二：当一回“网络侦探”，看看数据包长什么样（抓包分析）#

  • 想达到什么效果：你现在只知道“通”和“不通”，但你不想知道数据包在路上到底经历了什么吗？比如，你 Ping 百度的时候，你的电脑是怎么找到它的？中间经过了几个“快递中转站”？
  • 可以尝试什么技术：tcpdump（抓包工具） + traceroute（路由追踪工具）。
  • 实现思路（大白话）：
    1. 打开一个终端，输入 sudo traceroute -n baidu.com。你会看到一串 IP 地址，每一个都代表一个“路由器节点”。这就像你寄了一个快递，快递公司给你展示了它经过的每一个中转站的编号。
    2. 再打开另一个终端，输入 sudo tcpdump -i any icmp。这个命令会监听你电脑上所有的 ICMP 协议数据包（Ping 用的就是 ICMP）。
    3. 然后在第一个终端里 Ping 百度：ping baidu.com。这时，第二个终端里会跳出密密麻麻的“对话记录”，显示你的电脑发出了请求，百度服务器回复了你。这就像你在快递包裹上装了一个 GPS 追踪器，能实时看到它到了哪里。

玩点三：从“租户”变成“房东”，自己搭个 DNS 服务器（服务搭建）#

  • 想达到什么效果：你现在用的是 8.8.8.8（Google 的公共 DNS）或者 114.114.114.114（国内公共 DNS）。你能不能在自己的虚拟机上搭一个 DNS 服务器，让自己成为“电话本”的主人？
  • 可以尝试什么技术：bind（Linux 上最常用的 DNS 服务软件）。
  • 实现思路（大白话）：
    1. 用 yum install bind bind-utils 安装 DNS 服务软件。
    2. 修改配置文件 /etc/named.conf，告诉它“我要管理一个叫 myhome.lab 的区域”。
    3. 创建一个区域文件，在里面写上：www.myhome.lab 对应的 IP 是 192.168.1.100，ftp.myhome.lab 对应的 IP 是 192.168.1.101。这就像你在电话本里手动写上：“张三的电话是 138xxxx，李四的电话是 139xxxx”。
    4. 启动服务，然后把你自己电脑的 DNS 改成指向你自己的虚拟机 IP（比如 192.168.1.100）。这时你再 Ping www.myhome.lab，它就能解析到你设定的 IP 了。这种感觉，就像你从“租户”变成了“房东”，整个小区的门牌号都由你来定。

下一步的小项目推荐#

既然你刚完成了网络排障，我强烈推荐你趁热打铁，做一个《一键网络体检报告》的小项目。

  • 项目背景：把你刚才手动排障的四步，写成上面说的那个 Shell 脚本（check_network.sh）。
  • 你会学到：
    • Shell 脚本的基本结构（变量、条件判断、循环）。
    • 如何把命令的输出赋值给变量，并进行逻辑判断。
    • 如何让脚本输出颜色（比如绿色表示成功，红色表示失败），看起来更专业。
  • 为什么适合你：这个项目完美衔接了你刚学会的知识，而且成果立竿见影——以后每次网络出问题，你都可以自信地甩出这个脚本，一键定位问题。

等你把这个脚本写出来，可以随时找我 review，我们一起优化它。
