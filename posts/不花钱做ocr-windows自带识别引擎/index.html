不花钱做 OCR：用 Windows 自带的识别引擎批量识别网课截图

起因：AI 看不了图#

我上网课习惯截图，一节课下来十几张。我想让 AI 帮我把截图整理成笔记，结果卡在第一步：我用的模型是纯文本的，看不了图片。

思路很自然：那就先 OCR 成文字，再喂给它。

但我不想为这个花钱、也不想传到别人的服务器上（截图里有我的账号界面）。查了一圈发现：Windows 系统本身就自带 OCR 引擎，中文识别是现成的，一分钱不用花，也不联网。

Windows 自带 OCR 怎么调#

系统里有个 WinRT 的 OCR 接口（Windows.Media.Ocr），PowerShell 可以直接调。最关键的是类型加载那一行，不写的话后面全报错：

[Windows.Globalization.Language, Windows.Foundation, ContentType = WindowsRuntime] | Out-Null
$lang = New-Object Windows.Globalization.Language 'zh-Hans-CN'
$engine = [Windows.Media.Ocr.OcrEngine]::TryCreateFromLanguage($lang)

zh-Hans-CN 是简体中文引擎。想知道你机器上有哪些语言可用，可以列 AvailableRecognizerLanguages——一般装了中文语言包就有。

然后就是：图片 → SoftwareBitmap → RecognizeAsync → 拿 Text。异步调用在 PowerShell 里稍微绕一点，包一层等待就行。

提高识别率的一个笨办法：放大 2 倍#

第一次直接识别，效果一般。后来我在 OCR 之前先把图片等比放大 2 倍（GDI+ 双三次插值），识别率明显提升。

原理不难理解：OCR 引擎对小字号有下限，网课截图里的正文本来就不大，放大等于给它喂更清楚的笔画。代价是慢一点，但 17 张图也就几十秒。

搞定之后，17 张直播截图批量跑出 17 个 txt 文件，中文正文基本能用。

真正的难题：超长截图#

比这个麻烦得多的是另一批图——我把和 AI 的对话截成了长截图，尺寸是 560 宽 × 14000~23000 高。

第一反应是等比缩放到能处理的尺寸，结果文字直接糊成一团，识别出来全是垃圾。

原图直接喂？报错：

The parameter is incorrect
Image dimensions are too large

原因是 OCR 引擎有 MaxImageDimension 限制，超过就拒绝处理。

解法：切片 + 重叠 + 拼接#

最后方案是这样的：

  1. 先放大 2 倍（同上，保清晰度）；
  2. 纵向切片，每片高 2400px；
  3. 相邻切片重叠 100px；
  4. 逐片 OCR，把文本按顺序拼起来。

重叠那 100px 是关键。不重叠的话，切割线正好穿过一行字，那一行两边都识别不出来，内容就丢了。留 100px 冗余，被切断的行至少在某一片里是完整的。

6 张超长截图，最后识别出 2263 行文本，内容完整。

小坑：PowerShell 构造 Rectangle#

切片要用 System.Drawing.Rectangle，我一开始写：

New-Object Rectangle(0, $y, $w, $h)     # ❌ 这样不行

PowerShell 的 New-Object 不吃这种 C# 风格的构造调用，得用 -ArgumentList：

New-Object System.Drawing.Rectangle -ArgumentList 0,$y,$w,$h   # ✅

必须承认的局限：公式识别很烂#

中文正文识别得不错，但数学公式基本全废：

  • 上标下标丢失（sin²x 变成 sin2x 或 sinx）
  • 括号、分数线错乱
  • 希腊字母乱认

我的处理办法是：靠数学上下文重建，并且明确标注哪些是推断的。比如整理笔记时会写"这里的 sin²x 是根据上下文推断的，请核对"。

这一点我觉得比"假装识别对了"重要得多。OCR 出来的公式如果直接当成事实写进复习笔记，那就是给自己埋雷。

更好的一条路：能拿文字就别 OCR#

整理完我才想明白一件事：我截图的那些 AI 对话，本来是有分享链接的。

后来我试了另一条路：让 AI 用浏览器直接打开对话的分享链接，滚动到底把页面文字读出来——一次拿到 4783 个字符，零乱码，公式也是原样的文本。

对比一下：

方式结果
超长截图 + 切片 OCR2263 行，公式大量出错，要人工核对
浏览器直接读分享链接4783 字符，无乱码，公式正确

所以顺序应该是：

有原始文本 → 直接拿文本 有网页 → 用浏览器读 只剩图片了 → 才 OCR

我是反过来做的，先啃了最硬的骨头。写在这里提醒自己和你：动手之前先问一句"这个内容有没有文字版"，能省掉一整套切片拼接的活。

小结#

  • Windows 自带 OCR，免费、离线、中文可用，调用就是加载类型 + TryCreateFromLanguage；
  • OCR 前放大 2 倍，识别率明显提升；
  • 超长图必须切片，切片之间要重叠，否则丢行；
  • 公式识别不可信，必须标注不确定处；
  • 优先找文字来源，OCR 是最后的手段。
