第一次总结：我学到了什么？#

📋 Linux 基础命令（16 个核心指令）#

目录导航类#

  • pwd：打印当前工作目录，就像抬头看楼层指引牌，确认"我在哪儿"
  • ls：列出当前目录下的文件和文件夹，就像探头看鞋柜里有什么；-l 看详情，-a 看隐藏文件，-h 让大小人类可读
  • cd：切换目录，就像在办公楼里换房间；.. 回到上层，/ 回到根目录，~ 回到家目录，- 回到上次的目录
  • ~：当前用户的家目录快捷方式，root 的 ~ 是 /root，普通用户是 /home/用户名

文件管理类#

  • mkdir：创建文件夹，-p 可以一次性创建多层目录
  • cp：复制文件或文件夹，-r 复制文件夹，-i 覆盖前询问
  • mv：移动文件，或者在同一目录下重命名

内容操作类#

  • cat：查看小文件内容，或者配合 > / >> 写入文件
  • echo：输出文字，配合 > 覆盖写入文件，>> 追加写入文件
  • >：重定向符号，把输出写到文件里（覆盖）
  • >>：重定向符号，把输出追加到文件末尾

查找与过滤类#

  • grep：在文件内容里搜索关键词，-r 递归搜目录，-i 忽略大小写，-n 显示行号，-v 反向匹配
  • find：在文件系统里搜索文件，-name 按名字，-type 按类型，-mtime 按修改时间，-size 按大小

权限与运行类#

  • ls -l：查看文件权限详情，就像看文件的"身份证"
  • chmod +x：给文件添加可执行权限，就像给门禁卡激活
  • ./：指定"在当前目录下"运行某个文件

用户切换类#

  • su -：切换到另一个用户（默认 root），- 表示同时加载目标用户的环境变量
  • exit：退出当前用户，回到切换前的用户

网络与排障类#

  • ping：测试网络连通性，就像喊一嗓子看对面答不答应；-c 指定次数
  • curl：像浏览器一样访问网址，-o 下载保存为指定文件名，-O 用原文件名保存，-I 只看响应头
  • sed：流编辑器，批量替换文本，s/旧/新/g 是替换语法，-i 直接改原文件
  • yum：CentOS 的软件包管理器，就像系统里的"应用商店"；install 安装，remove 卸载，makecache 刷新缓存

环境配置类#

  • locale：查看系统语言环境，就像看手机系统语言设置
  • ibus：Linux 的输入法框架，就像输入法的"应用商店"
  • ibus-daemon：输入法后台进程，让输入法真正"活过来"

🏆 编程思维与排障思维#

  • “先预览再执行"的习惯：sed 先不加 -i 看输出，rm 前先用 ls 确认，find -delete 前先不加 -delete 看结果
  • “目标驱动 → 遇到障碍 → 简洁反馈 → 果断止损 → 系统复盘” 的学习闭环
  • 排障四步法：现象 → 定位根源 → 查找替代方案 → 验证解决
  • 遇到环境硬伤时别恋战：保住核心任务闭环比死磕环境更重要

🎯 网络工程师方向启蒙#

  • 理解了 IP 地址 = 门牌号、DNS = 电话本、路由器 = 快递中转站、防火墙 = 小区门禁 这些核心比喻
  • 完成了 “更换软件源” 这一网络工程师的核心能力训练
  • 知道了下一步要学：Vim 编辑器、ip addr、ss、dig、tcpdump 等网络专项工具

这就是你到目前为止学到的全部家当！别看命令不多，但每一个你都在真实项目里用过、踩过坑、解决过问题。这可比光背命令扎实多了。

第二次总结：我们做了什么 & 容易踩哪些坑？#

📖 我们做了什么#

我们一起走过了一段从零开始的 Linux 实战之旅。让我帮你回忆一下，咱们一步步干了哪些事：

第一步：建了个"家”#

我们先在 /root 下建了一个叫 linux_learning 的工作区，里面分了三个房间：notes（放笔记）、scripts（放脚本）、backup（放备份）。然后用 cp 和 mv 把笔记复制了一份并重命名，算是学会了"整理档案柜"。

第二步：写了第一份"中文笔记"#

你发现终端里打不出中文，折腾了一圈 locale 和 ibus 都没搞定。最后我们用 cat > 笔记.txt <<EOF（输入内容后以 EOF 结束）把中文笔记写进了文件。

第三步：写了第一个"自动化脚本"#

我们用 echo 创建了 myscript.sh，然后兴冲冲地运行 ./myscript.sh，结果被系统拦住了——“Permission denied”！后来我们用 chmod +x 给脚本发了张"通行证"，再用 ./ 告诉系统"就在当前目录找"，终于成功跑起来了。你亲身体验了 Linux 的安全机制。

第四步：经历了一次"系统网络大急救"#

这是最刺激的部分。你发现 yum 报错 Could not resolve host，原来是 CentOS 7 官方源已经关门了。我们一步步排查：

  1. 先用 ping 8.8.8.8 确认网络通不通。
  2. 发现能 ping 通但 yum 不行，定位到是 DNS 和源的问题。
  3. 手动配 DNS（echo "nameserver 8.8.8.8" > /etc/resolv.conf）。
  4. 用 curl 下载阿里云的配置文件。
  5. 用 sed 把旧地址全部替换成阿里云地址。
  6. 最后 yum makecache 刷新缓存，系统"起死回生"。

第五步：学会了在用户之间"换身份"#

我们用 su - 在 root 和普通用户之间切换，结果踩了"路径迷路"的坑——切了用户后 ~ 指向变了，找不到之前的文件夹。后来学会了用绝对路径或者先 pwd 确认位置。

第六步：掌握了搜索和过滤的"火眼金睛"#

我们用 grep 在文件里搜关键词，用 find 在整个系统里找文件。就像有了一个超级管家，你说"帮我找所有 .txt 文件"，他就能翻遍整个屋子给你找出来。

⚠️ 容易踩哪些坑？（踩坑指南）#

坑 1：断网危机——小卖部关门了你还硬往那儿跑#

  • 现象：yum 报错 Could not resolve host，装不了软件。
  • 根源：CentOS 7 官方源已于 2024 年 6 月 30 日下线，相当于你家楼下的小卖部关门了。
  • 避坑方法：
    • 遇到官方源挂掉，立刻换备用源（阿里云、清华源、华为云）。
    • 操作顺序：配 DNS → 下载新配置文件 → 替换旧地址 → 刷新缓存。
  • 生活比喻：就像你发现常去的超市倒闭了，不要傻站着，掏出手机导航去另一家超市。

坑 2：打不出中文——买了钥匙但锁锈死了#

  • 现象：装了 ibus 输入法框架，但在 nano 里还是打不出中文。
  • 根源：CentOS 7 的古老终端和输入法框架兼容性差，就像你买了把新钥匙，但锁已经锈死了。
  • 避坑方法：
    • 别恋战！果断换方案：用 cat > 文件 <<EOF 配合 EOF 结束符写入。
    • 或者在图形界面的写字板里打好中文，再用 cp 复制到终端路径。
  • 生活比喻：遇到死胡同就别硬撞墙，绕条路走，核心任务是到达目的地，不是证明这条路能走通。

坑 3：路径迷路——在两套房子里找错了储物间#

  • 现象：从 root 切到普通用户后，敲 cd ~/linux_learning 报错"没有那个文件或目录"。
  • 根源：~ 是跟着当前用户走的。root 的 ~ 是 /root，普通用户的 ~ 是 /home/用户名。你在 root 下建的文件夹，切到普通用户后 ~ 指向就变了。
  • 避坑方法：
    • 切换用户后，先用 pwd 确认自己在哪。
    • 用绝对路径，比如 cd /root/linux_learning。
    • 或者先 su - root 切回管理员。
  • 生活比喻：你家有两套房，A 房和 B 房。在 A 房里说"去储物间"能找到东西，跑到 B 房再说"去储物间"就找不到了——因为两个房子的储物间位置不一样。

坑 4：粘贴和终止——快捷键水土不服#

  • 现象：按 Ctrl+V 想粘贴，结果没用；ping 一直刷屏停不下来。
  • 根源：Linux 终端的快捷键和 Windows 不一样。
  • 避坑方法：
    • 粘贴用 Shift + Insert（或者鼠标右键选"粘贴"）。
    • 终止运行用 Ctrl + C（救命键，一定要记住！）。
  • 生活比喻：你开着一辆车，油门卡住了停不下来（ping 刷屏），这时候要知道刹车踏板在哪（Ctrl+C）。

坑 5：忘了给脚本发"通行证"#

  • 现象：运行 ./myscript.sh 时被拒绝，提示 Permission denied。
  • 根源：新创建的脚本默认没有执行权限，就像你拿着一张没激活的门禁卡去刷门。
  • 避坑方法：
    • 创建脚本后，记得用 chmod +x 脚本名 赋予执行权限。
    • 运行前可以用 ls -l 确认权限里有没有 x。
  • 生活比喻：你买了一辆新车，但钥匙还没激活，得先去 4S 店开个权限才能开走。

坑 6：sed 直接改文件没预览#

  • 现象：用 sed -i 直接改了文件，结果改错了，想还原却发现没有备份。
  • 根源：-i 是直接修改原文件，没有后悔药。
  • 避坑方法：
    • 先预览再执行：先跑 sed 's/旧/新/g' 文件名（不加 -i）看输出对不对。
    • 确认无误后，再加 -i 执行。
    • 保险做法：sed -i.bak 's/旧/新/g' 文件名，会自动备份原文件为 文件名.bak。
  • 生活比喻：你让装修师傅刷墙，先让他刷一小块给你看看颜色对不对，满意了再让他刷全屋。

这就是我们一起走过的路和踩过的坑。别看坑不少，但每一个坑你都亲自爬出来过，这才是最宝贵的经验——比背 100 个命令都值钱。

第三次总结：以后可以怎么玩得更好？#

你已经掌握了 16 个核心命令，完成了 3 个实战项目，踩过 6 个坑并成功爬了出来。接下来，我给你 4 条优化或扩展方向，每一条都是你资料库里规划好的下一步，直接拿来就能用。

方向一：跨过 Vim 这道门槛——从"记事本"升级到"专业编辑器"#

  • 想达到什么效果：以后改网络配置文件（比如 IP 地址、DNS 设置、Nginx 配置）不再依赖 cat 覆盖写，而是像用 Word 一样直接打开文件、定位到某一行、修改、保存。
  • 可以尝试什么技术：Vim 编辑器。它虽然上手有点陡，但一旦习惯了，效率碾压所有图形界面编辑器。
  • 实现思路：
    1. 打开终端，敲 vimtutor，这是 Vim 自带的互动教程，30 分钟就能过一遍。
    2. 记住四个救命操作：
      • i：进入插入模式（拿起笔准备写字）
      • Esc：退出插入模式（放下笔）
      • :wq：保存并退出（写完合上本子）
      • :q!：不保存强制退出（撕掉草稿走人）
    3. 然后在 notes 目录下用 Vim 创建第一个文件：vim notes/first_vim_note.txt，按 i 写一句话，按 Esc，再按 :wq 回车保存退出。
  • 生活比喻：你以前用 cat 写文件，就像用签字笔在便利贴上写字；用 Vim 写文件，就像打开 Word 文档，可以随意定位、修改、排版。虽然一开始要记几个快捷键，但用熟了比鼠标点来点去快十倍。

方向二：练熟网络专项命令——从"会用 ping"到"能用 tcpdump 抓包"#

  • 想达到什么效果：遇到网络问题，不再只会 ping 一下，而是能用一套组合拳精准定位问题——是 DNS 挂了？端口没开？还是路由不通？
  • 可以尝试什么技术：四个网络专项命令：ip addr、ss、dig、tcpdump。
  • 实现思路：
    1. ip addr：代替过时的 ifconfig，查看网卡 IP 和状态。就像看自家门牌号。
    2. ss -tulnp：查看系统监听了哪些端口。就像看家里哪些窗户开着通风。
    3. dig baidu.com：查看 DNS 解析过程，比 ping 更详细。就像查电话本，看对方号码到底是多少。
    4. tcpdump -i ens33 port 80 -c 10：抓取经过网卡 ens33 的 80 端口的前 10 个数据包。就像在门口装了个窃听器，偷听谁在跟你的服务器说话。
  • 生活比喻：你以前排障就像站在门口喊一嗓子"有人吗？"（ping），现在你学会了敲门、看猫眼、查监控、甚至装窃听器——手段多了，问题定位就准了。

方向三：搭建个人"网关服务器"——把虚拟机变成一个迷你路由器#

  • 想达到什么效果：让你的虚拟机不仅能自己上网，还能给其他设备分配 IP、转发流量、设置防火墙规则。这是从"Linux 用户"迈向"网络工程师"的关键一步。
  • 可以尝试什么技术：配置静态 IP、开启内核转发、使用 firewalld 或 iptables 设置防火墙规则。
  • 实现思路：
    1. 配置静态 IP：用 Vim 修改 /etc/sysconfig/network-scripts/ifcfg-ens33，把 IP 设为固定地址（比如 192.168.1.100），然后重启网卡。
    2. 开启内核转发：敲 sysctl net.ipv4.ip_forward=1，让你的虚拟机具有"路由转发"能力。
    3. 防火墙实战：安装 nginx（yum install nginx），然后用 firewalld 设置规则——只允许你宿主机的 IP 访问 80 端口，其他全部拒绝。
  • 生活比喻：你家的路由器就是一个"网关"，它负责把你家的设备和外面的互联网连接起来。你现在要做的事，就是自己动手做一个迷你版的路由器。

方向四：建立"排障日志"——把你的经验变成可复用的资产#

  • 想达到什么效果：以后再遇到同样的问题，不用重新想一遍解决方案，翻开日志直接抄答案。面试时也能拿出真实的排障案例来展示。
  • 可以尝试什么技术：在 notes 目录下用 Vim 创建一个 network_issues.md 文件，用 Markdown 格式记录。
  • 实现思路：

    1. 打开终端，敲 vim notes/network_issues.md。

    2. 按 i 进入插入模式，写下第一条记录，格式可以参考：

      # 排障日志
