背景#

今天从零搭了一个个人博客:用 Hugo(静态网站生成器)+ PaperMod(主题)搭建,文章在 Obsidian(笔记软件)里写,最后部署到 GitHub Pages 免费托管。

为什么这么组合?因为这套流程的好处是:写文章就像平时记笔记一样简单,保存后一键发布,全世界都能看到,而且完全免费、没有服务器费用、速度还很快。

听起来很美好,对吧?但实际走下来,一共踩了 7 个坑,每一个都真实经历过、排查过、解决过。这篇文章按 现象 → 根源 → 解决 → 教训 四步拆解每个坑,希望看到的人能少走弯路。

坑 1:发布后网页没有样式,白底一片#

现象

网站构建、推送都显示成功,但打开线上网址,页面是纯文字白底——标题、排版、颜色全没了,就像一份没排版的 Word 文档。奇怪的是,本地预览完全正常,样式好好的。

根源

网站生成时,每个样式文件都附带了一个"完整性校验值"(SRI,类似文件的指纹)。浏览器加载样式前会先算一遍指纹,对不上就拒绝加载整个样式表。

问题出在推送环节:Windows 上的文件换行符是 CRLF(回车+换行),而 git 推送到 GitHub 时,默认会自动转成 LF(只换行)。这一转,文件字节就变了,指纹对不上 → 浏览器拒收样式 → 白屏。

一句话:指纹是按 Windows 版文件算的,线上却是 Unix 版文件,对不上。

解决

在配置文件里关掉完整性校验:

[params.assets]
disableFingerprinting = true

这里还藏着一个更隐蔽的坑:这个配置必须放在配置文件最末尾。有一次我把它写在中间,它把后面所有的配置都"吞"进自己名下,导致内容目录失效,构建出来文章全没了——当时吓出一身冷汗,重建才找回。

教训

  • 配置文件(Toml 格式)里,“子配置块"必须放在文件末尾,否则会吞掉后面的键值。
  • 遇到"本地好好的,线上坏了"的问题,优先怀疑:编码、换行、校验这类"看不见的差异”。
  • 就像做饭:锅里的菜和端上桌的菜是同一份,但如果装盘时被换了调味料,味道就不对了。

坑 2:本地预览点文章,却跳到了线上网站#

现象

在本地预览页面(浏览器地址栏是 127.0.0.1:1313)上,点一篇文章的卡片,浏览器却"啪"地跳到了线上的网址(ggjfx.github.io)。而且线上那篇可能还没发布,于是显示无法访问此页面。

根源

Hugo 生成文章链接时,用的是"绝对地址"——就是根据配置文件里的线上地址(baseURL)拼出来的完整网址。所以本地预览页面上的链接,天生就写着线上的地址。

这就像:你在家里贴了一张外卖电话,但电话号码写的是邻居家的——你在家拨,当然打到邻居家去了。

解决

本地预览启动时,加一个参数把链接改成本地地址:

hugo server --baseURL http://127.0.0.1:1313/

--baseURL 就是"临时把线上地址换成这个",只对本次预览生效,不影响线上。

教训

  • 预览命令不能偷懒,这个参数必须带。
  • 后来我把它写进了桌面的"本地预览.bat",双击就自动带参数启动,不用每次手敲。

坑 3:顶部菜单也跳云端#

现象

修好了文章链接,结果发现顶部菜单(首页/文章/标签)点哪个都还是跳线上。

根源

这次不是 Hugo 的锅,是主题本身的问题:PaperMod 主题在渲染菜单时,用了一个函数(absolute URL)强制把所有菜单链接转成绝对地址。这是主题写死的,配置文件里怎么改都没用。

解决

把主题的头部模板复制到站点目录,把里面强制转绝对地址的代码改成相对路径:

themes\PaperMod\layouts\_partials\header.html
        ↓ 复制到
layouts\_partials\header.html   (改 absLangURL → relLangURL)

这就是 Hugo 的"覆盖机制":站点目录里有同名文件,就用站点的,主题的不生效。好处是主题以后更新,我的修改也不会丢。

教训

  • 改主题功能,永远用"覆盖",不要直接改主题本体。
  • 排查问题要有耐心:修好一个,要顺手检查同类的所有位置(文章链接修好了,菜单、站标、按钮都检查一遍)。

坑 4:bat 快捷方式打不开#

现象

为了方便,做了两个双击启动的脚本(打开博客.bat、本地预览.bat),结果双击后没反应或闪退,浏览器也没打开。

根源

bat 文件里写了中文(注释和窗口标题)。Windows 的 cmd 用 GBK 编码读文件,而文件是 UTF-8 编码保存的,中文全变乱码,乱码里还混进了破坏命令的字节——start 那行命令直接被搞坏了。

这就像:给机器人的指令卡上写了它看不懂的语言,机器人直接把指令卡扔了。

解决

把 bat 内容全部改成英文,一行中文都不留:

@echo off
cd /d D:\my-Blog
start "HugoServer" cmd /k "hugo server --baseURL http://127.0.0.1:1313/"
timeout /t 4 /nobreak >nul
start "" "http://127.0.0.1:1313/"

教训

  • bat 文件 = 纯英文,注释也英文。
  • 想给 Windows 脚本配中文说明,用文档文件(md),别用 bat 注释。

坑 5:手机打开显示的还是旧版#

现象

改了一堆样式,电脑上看都是新的,结果手机打开还是旧的样子,怎么刷新都没用。

根源

样式文件的名字不带版本号(比如固定的 stylesheet.css),浏览器就会把它缓存起来。手机浏览器缓存尤其"顽固",普通刷新它觉得"没变",直接拿缓存给你看。

这就像:快递柜里有个老箱子,你往里面放新东西,但取件时还是拿到旧箱子——因为柜子认箱子上的名字,而名字没变。

解决

手机测试一律用无痕窗口(隐私模式):无痕窗口默认不读缓存,打开的一定是最新版。

iPhone Safari:设置 → Safari → 清除历史记录与网站数据; 安卓 Chrome:地址栏左侧点锁/信息图标 → 网站设置 → 清除数据,或直接开无痕。

教训

  • 验证改动前,先确认自己看的是不是最新版——这是排查问题的第一步,也是最后一步(很多时候"问题"根本不存在,只是缓存)。
  • 给别人发网站链接时,提醒一句"刷新一下",能省掉很多误会。

坑 6:localhost 拒绝连接#

现象

本地预览服务器明明在跑,浏览器输入 localhost:1313 却提示拒绝连接,打不开。

根源

预览服务器只监听了 IPv4 地址(127.0.0.1),而 localhost 这个名字,系统有时会解析成 IPv6 地址(::1)。两个地址就像两栋楼,服务器只在一栋楼开门,浏览器去了另一栋,当然没人开门。

解决

地址直接用 IP,别用名字:

http://127.0.0.1:1313/

教训

  • 遇到"拒绝连接",先试试换地址写法(名字 ↔ IP、带不带 www、http/https)。
  • 这类"名字解析"问题很常见:localhost、127.0.0.1、::1 是三个不同的东西。

坑 7:网络环境(GFW)#

现象

github.com 网页打不开,git 推送也失败;好不容易能打开网页了,命令行工具又报证书吊销检查失败。

根源

网络环境限制导致访问 GitHub 困难。装加速器(Watt Toolkit / Steam++)后,网页能开了,但它用的是"中间人"方式(本地代理 + 自己签发的证书)。浏览器信任这个证书,而命令行工具(git/curl)默认要检查证书吊销状态,查不到就拒绝连接。

解决

命令行工具单独配置,让它们信任这个环境:

git config --global http.sslBackend schannel
git config --global http.schannelCheckRevoke false

curl 使用时加参数:

curl --ssl-no-revoke https://...

教训

  • 工具能通,不代表命令行能通——浏览器、git、curl 是三个独立的世界,要分别配置。
  • 网络问题要分层排查:网页打不开?命令行打不开?推送失败?分别是不同的问题。

速查表#

坑一句话关键命令/配置
1. 线上无样式SRI 校验被换行符破坏disableFingerprinting = true(放配置末尾)
2. 预览跳线上链接按 baseURL 生成hugo server --baseURL http://127.0.0.1:1313/
3. 菜单跳线上主题强制绝对地址覆盖 header.html,改用相对路径
4. bat 闪退中文编码乱码bat 全英文
5. 手机看旧版CSS 缓存无痕窗口
6. localhost 拒绝IPv6/IPv4 差异用 127.0.0.1
7. 推不上去网络环境schannel + 关吊销检查

总结#

七个坑,一半是"编码/换行"问题,一半是"链接指向"问题,还有两个是环境问题。核心体会:

  1. 配置文件改动要小心,位置和格式都可能埋雷——改之前先备份,改完先本地验证。
  2. 线上和本地是两套东西,链接、缓存、构建方式都不同,“本地好的"不代表"线上好的”。
  3. 遇到问题先确认环境:缓存清了吗?地址对吗?编码对吗?——一半的问题出在"我看的不是最新版"。
  4. 所有坑都要记下来,第二次就不会再踩了。这篇文章就是我的第一份"踩坑账本"。
