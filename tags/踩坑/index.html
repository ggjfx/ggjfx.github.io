踩坑

从零搭建个人博客:今天踩过的坑全记录

背景 今天从零搭了一个个人博客:用 Hugo(静态网站生成器)+ PaperMod(主题)搭建,文章在 Obsidian(笔记软件)里写,最后部署到 GitHub Pages 免费托管。 为什么这么组合?因为这套流程的好处是:写文章就像平时记笔记一样简单,保存后一键发布,全世界都能看到,而且完全免费、没有服务器费用、速度还很快。 听起来很美好,对吧?但实际走下来,一共踩了 7 个坑,每一个都真实经历过、排查过、解决过。这篇文章按 现象 → 根源 → 解决 → 教训 四步拆解每个坑,希望看到的人能少走弯路。 💡 阅读说明:标签颜色 —— 现象 / 根源 / 解决 / 教训 坑 1:发布后网页没有样式,白底一片 现象 网站构建、推送都显示成功,但打开线上网址,页面是纯文字白底——标题、排版、颜色全没了,就像一份没排版的 Word 文档。奇怪的是,本地预览完全正常,样式好好的。 根源 网站生成时,每个样式文件都附带了一个"完整性校验值"(SRI,类似文件的指纹)。浏览器加载样式前会先算一遍指纹,对不上就拒绝加载整个样式表。 问题出在推送环节:Windows 上的文件换行符是 CRLF(回车+换行),而 git 推送到 GitHub 时,默认会自动转成 LF(只换行)。这一转,文件字节就变了,指纹对不上 → 浏览器拒收样式 → 白屏。 一句话:指纹是按 Windows 版文件算的,线上却是 Unix 版文件,对不上。 解决 在配置文件里关掉完整性校验: [params.assets] disableFingerprinting = true 这里还藏着一个更隐蔽的坑:这个配置必须放在配置文件最末尾。有一次我把它写在中间,它把后面所有的配置都"吞"进自己名下,导致内容目录失效,构建出来文章全没了——当时吓出一身冷汗,重建才找回。 教训 配置文件(Toml 格式)里,“子配置块"必须放在文件末尾,否则会吞掉后面的键值。 遇到"本地好好的,线上坏了"的问题,优先怀疑:编码、换行、校验这类"看不见的差异”。 就像做饭:锅里的菜和端上桌的菜是同一份,但如果装盘时被换了调味料,味道就不对了。 坑 2:本地预览点文章,却跳到了线上网站 现象 ...
