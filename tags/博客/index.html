从零搭建个人博客:今天踩过的坑全记录

背景 今天从零搭了一个个人博客:Hugo + PaperMod 主题,用 Obsidian 写笔记,部署到 GitHub Pages。全程一共踩了 7 个坑,每一个都真实经历过、排查过、解决过。写下来,一是给自己留个记录,二是希望看到的人能少走弯路。 坑 1:发布后网页没有样式,白底一片 现象:线上网站打开是纯文字白底,排版全乱,本地却正常。 根源:网页带了完整性校验(SRI),而 git 推送时把文件的换行符从 Windows 格式(CRLF)转成了 Unix 格式(LF),文件字节变了 → 浏览器校验失败 → 整个样式表被拒收。 解决:配置里关掉校验(disableFingerprinting = true)。 教训:配置项的位置也有讲究——它必须放在配置文件末尾,放在中间会把其他配置"吞掉",导致内容目录失效、文章全丢(这个我也踩了,重建找回)。 坑 2:本地预览点文章,却跳到了线上网站 现象:在 localhost 预览页点文章,浏览器却打开了云端网址。 根源:Hugo 用 baseURL(线上地址)生成绝对链接。 解决:本地预览启动时加参数:hugo server --baseURL http://127.0.0.1:1313/,把链接改成本地地址。 教训:预览命令不能偷懒,参数必须带。 坑 3:顶部菜单也跳云端 现象:修好了文章链接,结果点顶部菜单(首页/文章/标签)还是跳线上。 根源:主题模板强制把菜单链接转成绝对地址。 解决:复制主题的头部模板到站点目录,把绝对地址改成相对路径,一劳永逸。 教训:改主题功能要"覆盖"而不是"修改"主题本体,不然主题更新就白改了。 坑 4:bat 快捷方式打不开 现象:双击做好的启动脚本,没反应或闪退。 根源:bat 文件里写了中文,Windows 的 cmd 用 GBK 编码读 UTF-8 中文,乱码把命令搞坏了。 解决:bat 内容全部改英文。 教训:bat 文件 = 纯英文,注释也英文。 坑 5:手机打开显示的还是旧版 现象:改了一堆样式,手机上怎么刷新都是旧的。 根源:样式文件名不带版本号,手机浏览器缓存严重。 解决:手机测试一律用无痕窗口。 教训:验证改动前,先确认自己看的是不是最新版。 坑 6:localhost 拒绝连接 现象:浏览器打不开本地预览。 根源:预览服务器只监听 IPv4(127.0.0.1),而 localhost 有时会被解析成 IPv6(::1)。 解决:地址直接用 http://127.0.0.1:1313/。 教训:遇到连接问题,先换个地址写法试试。 坑 7:网络环境(GFW) 现象:github.com 打不开,git 推送失败。 根源:网络环境限制,命令行工具还会遇到证书吊销检查失败。 解决:装 Watt Toolkit(Steam++)加速;命令行配置 http.sslBackend schannel + 关闭吊销检查;curl 加 --ssl-no-revoke。 教训:工具能通不代表命令行能通,两者要分别配置。 总结 七个坑,一半是"编码/换行"问题,一半是"链接指向"问题,还有两个是环境问题。核心体会: ...
