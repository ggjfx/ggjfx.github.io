我给 AI 助手加了一道安全门：装插件前先扫一遍

起因：我想给它装两个插件 用 OpenClaw 一段时间后，我开始想给它加点东西。看上了两个： 一个网关看门狗（openclaw-cli）：能监控服务、挂了自动重启、还有个网页监控面板。听起来很省心。 一个运维防呆技能（openclaw-ops-guardrails）：号称能规范排障流程、防止误操作。 我一个云计算专业的学生，服务动不动就挂，这两个都挺对我胃口。差点就直接装了。 但我的工作区里有一条硬规矩：装任何新技能、跑任何外部代码之前，必须先过一遍安全扫描。这条规矩是之前定的，本来我以为纯属仪式感——这次它真拦住了东西。 先说结果：两个都没装 扫描用的是一个叫 SkillSpector 的开源工具，我给它包了一层脚本，规则很简单：风险分 > 50 就是 BLOCKED，不许装。 第一个：77 分，HIGH openclaw-cli 扫出来 71 项发现，总分 77/100。其中最重的三条： 记忆投毒（Memory Poisoning）：代码里存在操纵 AI 记忆和状态的行为； 提权 / 凭据访问：会去读 .env 这类存密钥的文件； 中危一堆：跳过确认的自动决策、后台进程常驻等。 说句公道话：它是个看门狗工具，“重启服务"“常驻后台"本来就是它的本职工作，被标出来不算冤。但**“读 .env"和"改 AI 的记忆"这两条，跟看门狗没关系**。而且它是个人开发者的第三方社区包，不是官方组件——我一个新手，没能力逐行审代码，那就只能认扫描结果。 第二个：连官方仓库自己都说它可疑 第二个更有意思。它根本不是 npm 包，是技能市场里的一个技能。我一查： 市场官方的 verify 直接失败，状态是 status_not_clean； 安装命令自己就拒绝执行，非要我加一个 --acknowledge-clawhub-risk（我知道有风险还是要装）参数才肯继续； 官方安全审计给了两条高置信度警告： 93% 置信：它的故障手册里明确教你把审批开关关掉（ask=off），而且全文没有任何防护边界提醒； 90% 置信：一条排查命令直接把网关 token 明文写在命令行里，也没提醒这会泄进 shell 历史和进程列表。 杀毒引擎扫它是 64/64 干净——它不是病毒，它是在教你养成危险习惯。一个"防呆技能”，反手教我关掉防呆，这就很讽刺了。 看到这我就没兴趣了。当时我给自己的回复就三个字：都不要。 过程中踩的几个坑 顺手记一下，都是重复劳动的来源： 扫描器直接吃 GitHub 地址会报 “target not found”。解决办法是先把包的 tarball 下到本地再扫本地目录。 扫描器"发现了风险"时退出码是 1。我的脚本一开始把非 0 当失败处理，结果风险最大的那次反而被当成"脚本挂了”。教训：永远解析 JSON 报告，别只看退出码。 它的 WARNING 输出走的是 stderr，在新版 PowerShell 里会直接触发 NativeCommandError，整个脚本红一片。得单独处理。 装扫描器本身也有坑：它依赖的 yara-python 在 Windows 上没有现成的安装包，源码编译又要装 Visual Studio 编译器。我最后是找了个预编译好的 wheel 文件塞进去的。 我从这件事里学到什么 第一，安全门要卡在"决定装之前”，不是"装完出问题之后"。 如果我先装了，看门狗常驻后台、能读 .env、还能改它自己的记忆——出了问题我根本查不出来是哪一步坏的。 ...

给 OpenClaw 升级"上网"能力：从只能读文字，到会开浏览器

起因：我发现它"上网"其实很弱 之前那篇《部署 OpenClaw 有什么用？》里我说过，我主要拿它干三件事：查资料、找电子书、管理博客。查资料是排第一的，所以"上网"这个能力好不好用，对我特别重要。 用了一段时间，我越来越觉得它的"上网"有点弱。具体表现是：让它搜东西，结果经常又少又不准；有些网页让它看，它说打不开、抓不到内容。一开始我以为是自己不会用，后来问了才知道——它本来就只有"文字级"的上网能力。 为什么弱？拆开看就明白了 它上网靠两个工具： 搜索：用的是一种叫 DuckDuckGo 的免费搜索源，不需要注册、不用花钱。但代价就是：结果少、对中文不友好、还时不时被限流。免费的嘛，能理解。 抓网页：只能把网页的纯文字"读"出来。遇到靠 JavaScript 动态加载的网页（现在很多网站都是），或者需要登录的页面，它就抓瞎了。 最关键的其实是第三点：它没有被授权使用浏览器。OpenClaw 本身带一个浏览器控制功能，可以让 AI 真的打开一个浏览器、像人一样操作网页。但默认配置只给了它"读文字"的工具，没给"开浏览器"的权限，等于有车钥匙却没给他驾照。 怎么升级的：改配置 + 重启 听起来很复杂，其实就是改一行配置、重启一下服务。过程大概是这样： 在配置文件里给它加上浏览器工具的权限； 重启 OpenClaw（会断线几秒钟）； 启动一个独立的浏览器，归它管。 这里我踩了一个小坑：第一次重启后浏览器功能没生效，查日志发现是插件没被显式启用，自动启用没注册上。把配置里补上插件开关、再重启一次就好了。 还有个细节：它用的浏览器是独立的（Edge 的一个独立配置），跟我平时自己用的浏览器完全分开，不会动我的收藏、密码、登录状态。这个设计挺安心的。 现在能干什么了 升级完，它从"只能读文字"变成了"真的会用浏览器"： 打开真实网页，等页面渲染完再看内容； 点击、翻页、填表单； 截图给我看； 之前打不开的动态页面，现在也能看了。 为了验证，我让它打开了我自己的博客首页。它不但打开了，还截图发给我，并且读出了页面上的内容：导航栏、最新三篇文章的标题、底部的 Hugo + PaperMod 标识，全都对。 一点小遗憾 搜索源还是免费的 DuckDuckGo，中文搜索结果依然一般。想更准的话，可以再配一个叫 Kimi 的搜索源（注册拿个 API Key 就行，有免费额度）。这个不急，等哪天觉得搜索不够用了再弄。 总结 这次升级给我的感受是：OpenClaw 的能力不是定死的，很多"弱"其实只是没配置好。它本来就有浏览器这个"大招"，只是默认没开。改一行配置、重启一下，上网能力就从"文字版"变成了"真人版"。 以后它帮我查资料、找书，应该会顺手很多了。

部署 OpenClaw 有什么用？——一个新手的使用体验

背景：我为什么要折腾这个 先说下我的水平：云计算专业的学生，会一点 Linux，但命令行、git、部署这些都不熟，全是现学现卖。 我搭这个博客的时候，发现几乎所有东西都要问 AI：这个命令什么意思、这个报错怎么办、这个配置怎么改。但网页版 AI 有个很烦的问题——换个对话就不记得我了，同一个问题过两天又得从头解释一遍。 后来我知道了 OpenClaw：一个开源的 AI 助理网关，可以装在自己电脑上。装好之后，它就是一个“属于你自己的 AI”——有记忆、能干活，还能用我平时的聊天软件跟它说话。听起来正是我需要的，就动手试了试。 OpenClaw 是什么？大白话版 它就是跑在你自己的电脑（或服务器）上的一个程序。装好之后，你可以用 Telegram、微信、Discord 这些聊天软件跟它聊天，背后接的是各种 AI 大模型（Claude、GPT、DeepSeek 这些，甚至本地模型都行）。 跟“打开 ChatGPT 网页聊天”比，最大的区别是：它是你的，不是租来的。 数据、聊天记录都在你自己机器上，规则你定； 性格、语气、能干什么，都可以自己配置； 它不只是会聊天，还能帮你干活：查资料、跑命令、定时提醒、读写文件…… 打个比方：网页版 AI 像“去别人家借东西”，OpenClaw 是“在自己家养了一个管家”。 它是怎么工作的 其实原理不复杂： 你常用的聊天软件 Telegram / 微信 / Discord / WebChat ↓ OpenClaw Gateway 跑在你自己的机器/服务器上 ↓ AI 大模型 （Claude / GPT / DeepSeek） 记忆系统 （长期记忆） 工具/技能 （搜索 / 命令 / 文件） 拆开说就三步： 你在聊天软件里发消息（比如“帮我看下这个报错”）； 网关收到后交给 AI，AI 可以查记忆、调用工具（搜索、执行命令、读文件）； 结果再发回你的聊天窗口，就像跟朋友聊天一样。 我这段时间真实用到了什么 说几个我真在用的场景，按用得多不多排的： ...
